1. ТЕХНИЧЕСКИЙ СТЕК И ПРАВИЛА
---------------------------------------------------------------------
Backend : Python 3.11+, Flask, Flask-SQLAlchemy, SQLite (файл data/tiger.db).
          Только REST JSON API под префиксом /api/*.
Frontend: чистый HTML5 + CSS3 + vanilla JS (ES modules). БЕЗ webpack/vite,
          БЕЗ React/Vue/jQuery, БЕЗ CDN-зависимостей.
Файлы   : локальная папка uploads/, лимит 15 МБ на файл, только image/* и video/*.
Языки   : kk / ru / en — все тексты UI только через i18n-файлы.
Prod    : gunicorn (main.py: `from backend import create_app; app = create_app()`),
          плюс index.wsgi + .htaccess для Apache/mod_wsgi (опционально).

Жёсткие принципы:
1. Mobile-first: сначала стили для мобильных, затем @media (min-width: …).
2. Никакого хардкода текста в UI. Любая строка добавляется во ВСЕ три файла
   frontend/i18n/kk.json, ru.json, en.json (плоские ключи вида "tasks.round.live")
   и используется через t('key') или атрибут data-i18n. Поддержи подстановки {n}.
3. Роль решает сервер. Фронтенд скрывает кнопки, но проверка прав ОБЯЗАТЕЛЬНА
   в backend (декораторы @require_auth, @require_role, @admin_only).
4. Никаких новых зависимостей без добавления в requirements.txt.
5. Никаких миграций: схема только в backend/models.py. При изменении схемы —
   удалить data/tiger.db и пересоздать сид. Допустим мягкий список NEW_COLUMNS
   (ALTER TABLE ADD COLUMN при старте) для добавления колонок в существующую БД.
6. Ответ API всегда: { "ok": true, ... } или { "ok": false, "error": "code", "message": "…" }.
   HTTP: 200 ок, 400 валидация, 401 нет токена, 403 нет прав, 404 нет объекта, 413 файл велик.
7. Python: 4 пробела, snake_case, type hints в новых функциях, docstring у роутов.
   JS: ES-модули, camelCase, const/let, глобальная переменная только window.TIGER.
   CSS: переменные в :root (--clr-*, --space-*), классы kebab-case, БЭМ-подобно.
8. Любой пользовательский текст экранируется (escapeHtml) — защита от XSS.

3. РОЛИ И ПРАВА ДОСТУПА
---------------------------------------------------------------------
Роли: admin (администратор), leader (лидер команды), member (участник).

| Действие                                        | admin | leader | member |
|-------------------------------------------------|:-----:|:------:|:------:|
| Просмотр заданий / рейтинга                     |   ✔   |   ✔    |   ✔    |
| Отправка ответа на задание + файлы              |   ✔   |   ✔    |   ✘    |
| Ответы на вопросы теста                         |  ✘*   |   ✔    |   ✔    |
| Выбор карточки кабинета                         |   ✘   |   ✔    |   ✘    |
| Лайки за ответы команд (задания №3 и выше)      |   ✘   |   ✔    |   ✔    |
| Изменение состава команд, лидеров               |   ✔   |   ✘    |   ✘    |
| Ручная правка баллов                            |   ✔   |   ✘    |   ✘    |
| Просмотр всех ответов/файлов/выборов            |   ✔   |   ✘    |   ✘    |

* Админ не отвечает на вопросы, но управляет ходом теста.

Авторизация:
- Логин + общий пароль. Роль НЕ вводится пользователем, определяется по логину.
- Пароль участников/лидеров по умолчанию: BEKTUROV2026; пароль админов: TIGERADMIN2026
  (константы в config.py). В БД хранится password_hash (PBKDF2 через werkzeug), чтобы админ
  мог менять логин/пароль конкретного аккаунта.
- Логины: admin01…admin10; лидеры t01-leader…t08-leader; участники t01-p1…t08-p24.
- При входе создаётся AuthToken (32-байтный hex, TTL в часах из config), передаётся
  заголовком Authorization: Bearer <token>. Logout отзывает токен.
- team_id всегда берётся из токена/пользователя, а не из тела запроса
  (кроме админских эндпоинтов).

QuizAnswer(id, question_id, team_id, user_id, selected_index, is_correct, points)
  UNIQUE(question_id, user_id)  # один ответ на вопрос от КАЖДОГО участника

ScoreAdjustment(id, team_id, admin_id, delta, reason, created_at)
Message(id, user_id, from_admin, text, created_at, is_read)     # чат участник ↔ админ
TeamMessage(id, team_id, user_id, text, created_at)             # чат команды
StateVersion(key PK, version, updated_at)                        # версии для polling

Хелперы: bump(*keys) — увеличить версии; get_setting/set_setting для AppSetting.

Баллы команды = Σ Submission.points + Σ QuizAnswer.points + Σ ScoreAdjustment.delta.

5. «РЕАЛЬНОЕ ВРЕМЯ» (POLLING С ВЕРСИЯМИ)
---------------------------------------------------------------------
- Каждое изменение данных вызывает bump(...) соответствующих ключей:
  tasks, quiz, votes, leaderboard, teams, submissions, messages, teamchat, task3.
- Клиент раз в ~3–4 секунды вызывает GET /api/state → { versions:{…}, server_time }
  (ответ ~150 байт; перед ответом вызывает ensure_progress для теста и таймеров заданий).
- Если версия нужного раздела изменилась — клиент перезагружает только этот раздел (store.js).
- Таймеры на клиенте считаются локально от remaining_seconds, а не по часам телефона.

7. ФУНКЦИИ ЛИДЕРА / УЧАСТНИКА (app.html — SPA с нижней навигацией)
---------------------------------------------------------------------
Вкладки: Задания · Тест · Голосование (Сектор Голосование) · Рейтинг · Команда · Сообщения · Профиль.
Переключатель языка KK/RU/EN в шапке (хранится в localStorage вместе с token и user).

7.1 Задания
- Список опубликованных заданий с текстом, картинкой (если есть), максимальными баллами.
- Лидер отправляет ответ: текст + до N файлов (фото/видео, ≤15 МБ каждый, проверка на клиенте и сервере),
  может отредактировать/дополнить ответ, удалить свой файл. Участник видит задание и ответ команды, но не может отправлять.
- Для заданий №2 и выше есть таймер (TaskRound): пока таймер не запущен — «Администратор ещё не запустил задание»;
  во время running — баннер с круговым таймером и приём ответов; по окончании приём закрыт.
- «Запечатанные» (sealed) задания: если раунд закрыт и не идёт, текст скрыт плёнкой «🔒 Задание №N» для не-админов.
- Баллы и комментарий выставляет админ; результат виден команде.

7.2 Тест (синхронный, один вопрос на всех)
- Фазы: idle → question → standings → … → finished.
- Все видят ОДИН текущий вопрос и ОДИН таймер (по умолчанию 60 сек на вопрос, 15–20 сек на показ рейтинга).
- Каждый пользователь (лидер и участник) выбирает вариант один раз; ответ «принят», правильность не раскрывается
  до конца вопроса. Баллы всех правильных ответов суммируются в баллы команды.
- В фазе standings: правильный ответ, свой результат, сколько ответило, место команды в рейтинге.
- Картинки в вопросах (тип «Что на картинке?») показываются над вариантами.
- Финал: итоговый рейтинг.

7.3 Сектор Голосование — карточки кабинетов (Раунд 3)
- 6 «переворачивающихся» карточек (CSS 3D flip) №1…№6. Карточка → кабинет: 1→107, 2→108, 3→109, 4→110, 5→112, 6→113.
- Выбирать может только лидер; одна карточка — одной команде, одна команда — одна карточка (повторный выбор запрещён).
- Выбор атомарный (защита от гонки): UPDATE room_cards SET team_id=… WHERE number=… AND team_id IS NULL.
- Выбравший лидер видит сообщение с номером кабинета; остальные видят ТОЛЬКО какая команда какую карточку выбрала
  (кабинет другим скрыт — сервер не отдаёт room чужим).
- Когда все 6 карточек разобраны или команда выбрала — дальнейший выбор закрыт.
- Админ может скрыть весь блок карточек (AppSetting cards_visible) — участники его не видят.
- Раздел назван «Сектор Голосование» / «Сектор бойынша дауыс беру» / «Sector Voting».

7.4 Лайки за ответы команд (только задания №3 и выше)
- Константа LIKES_MIN_ORDER = 3. У заданий №1–2 лайков нет: по окончании времени они сразу переходят в closed.
- После окончания таймера задания №3/№4 (или по кнопке админа) фаза voting: в разделе «Голосование» показаны
  галереи ответов команд (текст + фото/видео). Каждый пользователь ставит один лайк на задание
  (можно изменить), за СВОЮ команду голосовать нельзя; только за команды, отправившие ответ.
- Админ может закрыть голосование (closed), снова открыть, сбросить лайки; видит рейтинг лайков.
- Сервер: попытка лайка там, где лайки выключены → 400 likes_disabled.

7.5 Рейтинг
- Отдельная страница: ТОП-10 команд с раскрытием полного списка («Показать всех»).
- Команда попадает в рейтинг, если есть хотя бы одна отправка/ответ/ручная правка баллов.
- Сортировка: баллы ↓, затем время последней активности ↑. На мобильных строки — карточки.

7.6 Команда
- Состав команды (лидер отмечен), чат команды (TeamMessage, лидер/участники пишут, лидер или админ могут очистить).

7.7 Сообщения
- Личный чат участника с администраторами (Message). Админ видит список диалогов, отвечает, может сбросить все.

7.8 Профиль
- Отображаемое имя, смена языка, выход. (PATCH /api/auth/profile)

8. ФУНКЦИИ АДМИНИСТРАТОРА (admin.html — SPA)
---------------------------------------------------------------------
Вкладки: Обзор · Команды · Задания · Тест · Голосование · Ответы · Сообщения.

- Обзор: счётчики (команды, участники, ответы, выбранные карточки, ответы теста), быстрые действия.

  история правок); сброс всех ручных правок.
- Задания: CRUD заданий (названия и тексты kk/ru/en, макс. баллы, публикация, порядок, картинка к заданию
  — загрузка/удаление в uploads/media); просмотр всех ответов и файлов, выставление баллов, удаление ответа,
  сброс всех ответов.
  ПУЛЬТ ТАЙМЕРА для каждого задания №2+: Начать / Начать заново, Пауза/Продолжить, +5/+15/−5 минут,

  «Закрыть голосование», «Снова открыть голосование» (только у заданий с лайками), «Сбросить таймер»
  (с опцией очистки лайков), поле «длительность (минуты)» + Сохранить. Круговой таймер вживую.
- Тест: открыть/закрыть тест; ПУЛЬТ: старт, «показать рейтинг сейчас», следующий/предыдущий вопрос,
  «вывести всем» любой вопрос из списка, +15с/+30с/−15с, пауза/продолжить, завершить, сброс теста,
  сброс ответов; настройки: время на вопрос, время показа рейтинга, автопереход (чекбокс), показывать результаты.
  РЕДАКТОР ВОПРОСОВ: добавить/изменить/удалить вопрос (текст и 2–6 вариантов × 3 языка, верный вариант, баллы),
  загрузка/удаление картинки к вопросу.
- Голосование: список карточек кабинетов (кабинет виден админу всегда), какая команда выбрала;
  «Освободить карточку», «Сбросить все карточки», переключатель «Скрыть/показать блок карточек»;
  галереи лайков по заданиям (рейтинг по лайкам), «Сбросить лайки».
- Сообщения: диалоги с участниками, ответ, сброс.

9. АЛГОРИТМ ТЕСТА (backend/quiz_engine.py)
---------------------------------------------------------------------
- ensure_progress(quiz) вызывается из /api/state и /api/quiz/state и пересчитывает расписание по phase_ends_at.
- Переходы выполняются условным UPDATE ... WHERE phase=? AND current_index=? — параллельные запросы
  сотен клиентов не могут перескочить вопрос дважды.
- Расписание: question (question_seconds) → standings (standings_seconds) → следующий вопрос (если auto_advance)
  → … → finished после последнего.
- Пауза: сохраняем paused_remaining, при resume пересчитываем phase_ends_at.
- Ответ: POST /api/quiz/answer {question_id, selected_index}; допустим только в фазе question
  для текущего вопроса, роли leader/member, один раз на (вопрос, пользователь); админ → 403.
- Баллы начисляются сразу (is_correct → points вопроса); команде суммируются.
- Пульт админа: POST /api/admin/quiz/control {action: start|reveal|next|prev|goto|extend|pause|resume|finish|reset}.
- Настройки: POST /api/admin/quiz/settings; тумблер: POST /api/admin/quiz/toggle.

АЛГОРИТМ ТАЙМЕРОВ ЗАДАНИЙ (backend/task3_engine.py)
- ensure_rounds() создаёт TaskRound для каждого задания с order >= 2 (TIMED_TASK_MIN_ORDER).
- Свойства: can_submit (phase == running), likes_enabled (order >= LIKES_MIN_ORDER),
  projects_visible (likes_enabled и phase ∈ voting/closed), can_like (likes_enabled и phase == voting),
  after_work_phase (voting, если лайки включены, иначе closed).
- ensure_progress(): если running и время вышло и не пауза → переход в after_work_phase (условным UPDATE).
- Действия админа: start, pause, resume, extend(±sec), finish, close, open (только при likes_enabled), reset.
- gallery_for(row, lang, user, force): карточки ответов команд для голосования, число лайков, флаг «мой лайк».
  Файлы чужих команд раздаются только когда projects_visible (или админу).
- Защита от двойного создания пульта при параллельных запросах (try/except на commit).

11. ФАЙЛЫ И БЕЗОПАСНОСТЬ
---------------------------------------------------------------------
- MAX_CONTENT_LENGTH ≈ 16 МБ (запас на multipart) + повторная проверка размера каждого файла (≤15 МБ).
- Разрешены только image/* и video/*; расширение — из белого списка; имя файла = uuid4 + расширение.
- Ответы команд: uploads/<submission_id>/…; картинки заданий/вопросов: uploads/media/…
- GET /api/files — только авторизованным: своя команда, админ, либо когда ответы открыты для голосования.
- 413 при превышении размера. Все мутации проверяют роль и принадлежность команде.
- Токены с TTL, отзыв при logout, пароли только в виде хешей.
- Публичные поля пользователей не содержат хешей и чужих логинов с паролями.

16. SMOKE-ТЕСТ (scripts/smoke_test.py) — ЧТО ДОЛЖЕН ПРОВЕРЯТЬ
---------------------------------------------------------------------
- Вход админа/лидера/участника, неверный пароль, роль по логину, отказ без токена (401).
- Задания: лидер отправляет ответ с файлом; участник — 403; файл >15 МБ → 413; не-image/video → 400.
- Админ: правка баллов, ручная правка баллов команды, рейтинг пересчитывается.
- Тест: старт, ответ лидера и участника, повторный ответ запрещён, админ не отвечает, автопереход фаз,
  next/prev/goto/extend/pause/resume/finish, баллы всех участников суммируются в команде.
- Карточки: лидер выбирает карточку, повторный выбор запрещён, чужую занятую нельзя, участник не может,
  остальные не видят кабинет чужих, админ освобождает, скрытие блока работает.
- Таймеры заданий: start/pause/extend/finish; у заданий №1–2 лайки отключены (400 likes_disabled),
  у №3–4 лайк работает, за свою команду нельзя, повторный лайк меняет выбор.
- Права: все админские эндпоинты отвечают 403 не-админу.
- Тест обязан быть идемпотентным: после запуска вернуть тайминги теста (60/15 сек) и состояние.
